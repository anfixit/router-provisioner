# Мониторинг роутеров и обновление по кнопке

Дата: 2026-08-25. Статус: согласовано, ждёт реализации.

## Зачем

Сегодня о поломке узнаёшь только тогда, когда кто-то пожалуется. Журнал на
роутере держит около суток и живёт в оперативной памяти, так что к моменту
разбора нужного окна обычно уже нет. Три роутера расползлись по версиям, и
понять это можно лишь зайдя на каждый по SSH.

Цель: владелец узнаёт о поломке раньше пользователей, имеет на руках разбор
случившегося и может обновить роутер, не подключаясь к нему.

## Что уже есть и переиспользуется

VPS `satx-us` (2.27.27.6, SSH 31408) несёт рабочий стек:

- Prometheus — собирает 14 узлов подписки (`nodes`) и инфраструктуру (`infra`),
  интервал 30 с;
- Alertmanager — **уже отправляет в Telegram двумя маршрутами**, срочным и
  обычным, в один чат;
- Grafana за Caddy, blackbox-exporter, правила в `rules.yml` на русском
  (`НодаУпала`, `XrayЛежит`).

Поэтому свой сторож, своя база и своя доставка в Telegram не пишутся. Роутеры
встраиваются в существующий стек.

### Оговорка про диск VPS

Синхронная запись на сервере идёт со скоростью 258 кБ/с (около 16 мс на
операцию), `iowait` 13 %, системное время 43 %, при нулевом `steal`. Контейнеры
прочли с диска более 700 ГБ при 93 МБ данных — страничный кеш не удерживает
ничего. Причина на стороне хостинга (корень смонтирован через `/dev/loop16`),
нагрузка владельца ни при чём: все пять контейнеров потребляют 0–1 % процессора.

Наши метрики добавят сотни рядов и погоды не сделают. Но машина, следящая за
остальными, сама нездорова — это стоит предъявить хостеру отдельно.

## Архитектура

Роутеры за NAT, scrape к ним невозможен. Поэтому обратная схема:

```
роутер: агент раз в 5 мин  ──POST──>  Pushgateway (VPS)
                            <──GET──   очередь заданий
                                          │
                                    Prometheus (scrape)
                                          │
                                    правила тревог
                                          │
                                    Alertmanager ──> Telegram
```

Отправка пробуется напрямую, при неудаче — через прокси. Обратный порядок
недопустим: сломанный VPN унёс бы с собой и способность сообщить о поломке.

## Этап 1. Файл ответов

Сейчас скрипт нельзя запустить без человека: `--yes` отвечает только на «да/нет»,
а подписку, узлы и домены он спрашивает по-настоящему и будет ждать ввода
бесконечно. Это блокирует и обновление по кнопке, и слежение за дрейфом: «как
должно быть» не записано нигде.

Вводится профиль `/etc/router-provisioner/profile` — ответы на все вопросы,
которые скрипт задаёт. При запуске с `--profile` вопросы берутся оттуда, а
отсутствующие в файле по-прежнему спрашиваются. Секреты (ссылка подписки) лежат
в нём с правами `600`.

Профиль решает три задачи разом: неинтерактивный запуск, эталон для сравнения и
воспроизводимая настройка нового роутера.

## Этап 1b. Запасной путь для YouTube

Страница YouTube ушла на прямой маршрут и держится на обходе DPI. Запасного пути
нет: изменится фильтрация — YouTube пропадёт совсем.

Новый хелпер раз в 15 минут проверяет, отвечает ли `www.youtube.com` по прямому
маршруту (запрос с настоящим адресом от внешнего резолвера, минуя FakeIP — иначе
проверка с роутера ничего не измеряет). Три неудачи подряд — `youtube.com`
уезжает из прямого списка обратно в туннель, событие уходит в метрики. Прямой
путь ожил — домен возвращается сам.

Владелец получает рекламу вместо чёрного экрана, и только на время поломки.

## Этап 2. Агент, метрики, тревоги

### Метрики

Агент отдаёт в формате Prometheus, с меткой `router="<имя>"`:

| Метрика | Смысл |
| --- | --- |
| `router_last_seen_timestamp` | момент отправки, основа для сторожа молчания |
| `router_singbox_running` | процесс жив |
| `router_config_valid` | `sing-box check` проходит |
| `router_policy_route_present` | правило `lookup netshift` на месте |
| `router_nodes_alive` / `router_nodes_total` | узлы подписки |
| `router_selected_node{group}` | выбранный узел каждой группы |
| `router_pin_respected` | закреплённый сервис на своём узле |
| `router_route_check{target}` | синтетическая проверка маршрута |
| `router_wan_up`, `router_wan_speed_mbits` | состояние аплинка |
| `router_singbox_errors{kind}` | ошибки за интервал по типам |
| `router_component_version{name,version}` | версии, включая версию скрипта |
| `router_config_drift` | хеш настроек разошёлся с профилем |
| `router_uptime_seconds`, `router_mem_available_bytes` | базовое здоровье |

### Синтетические проверки

Раз в 15 минут агент проверяет не самочувствие, а результат: Claude уходит на
закреплённый узел, YouTube — напрямую, Telegram — в туннель, `ya.ru` — мимо
всего. Ожидания берутся из профиля. Это ловит именно тот класс поломок, который
пришлось ловить руками, и ловит до жалоб.

### Тревоги

В существующий `rules.yml`, теми же словами и с той же разметкой срочности:

| Тревога | Условие | Канал |
| --- | --- | --- |
| `РоутерМолчит` | нет чек-ина 15 мин | срочный |
| `VPNНеПоднялся` | процесс мёртв или конфиг невалиден, 3 мин | срочный |
| `МаршрутСмыло` | нет правила `lookup netshift`, 3 мин | срочный |
| `ВсеУзлыМертвы` | `nodes_alive == 0`, 5 мин | срочный |
| `УзелОтказал` | закрепление ушло на резерв, 5 мин | обычный |
| `МаршрутНеТуда` | синтетическая проверка не сходится, 15 мин | обычный |
| `ОбходСломался` | YouTube ушёл на запасной путь | обычный |
| `КонфигурацияРазошлась` | хеш не совпал с профилем | обычный |
| `РоутерОтстал` | версия скрипта ниже последней | обычный |

Дребезг гасится штатным `for:` у Prometheus и группировкой Alertmanager;
своего кода для этого не пишется. Возврат в норму приходит отдельным
сообщением с длительностью.

### Суточный отчёт

Задание на VPS в 09:00 опрашивает Prometheus и шлёт одно сообщение: по каждому
роутеру аптайм, доля времени в норме, минимум и среднее живых узлов, число
переключений узла с причинами, прошли ли ночные работы, версии. Ниже — список
инцидентов: начало, длительность, что отказало, что сделала автоматика, чем
кончилось. Ошибки сгруппированы по типу с количеством. Подробности — ссылкой на
Grafana.

### Классификатор ошибок

Таблица сигнатур с человеческим смыслом, собранная из реальных случаев:

| Признак | Значение |
| --- | --- |
| `http2: client connection force closed` | норма, клиент закрыл соединение |
| все узлы мертвы при валидном конфиге | устаревший sing-box |
| нет `lookup netshift` | правило смыло перезапуском firewall |
| кроны вернулись на 9:13 и 9:17 | NetShift перезапустили из LuCI |
| серия `Link is Down` | кабель или порт |
| `Downshift … check cabling` | линия не держит гигабит |

Незнакомое попадает в отчёт как незнакомое, с текстом — это повод пополнить
таблицу, а не молча проглотить.

## Этап 3. Команды и обновление

Небольшой бот на VPS — единственный новый сервис, кроме Pushgateway.

- `/status` — состояние всех роутеров;
- `/log <роутер>` — последние ошибки с разбором;
- `/update <роутер>` — поставить задание на обновление;
- `/fix <роутер>` — перезапуск NetShift, возврат закреплений, ретайминг кронов;
- `/quiet 2h` — приглушить на время.

Задание кладётся в очередь, агент забирает его при следующем чек-ине и
выполняет: скачивает свежую версию, запускает с профилем неинтерактивно,
проверяет здоровье и рапортует. Не поднялось — откат на предыдущую версию.

`/update` и `/fix` требуют подтверждения в чате: это выполнение кода на чужом
роутере.

## Безопасность

- Токен бота живёт только на VPS. Роутер знает адрес Pushgateway и свой секрет —
  утечка с роутера друзей не даёт доступа к чату.
- Секрет передаётся заголовком, Pushgateway закрыт Caddy с проверкой заголовка,
  снаружи не доступен без него.
- Метрики не содержат доменов, имён устройств и адресов клиентов. Окно журнала
  прикладывается только при аварии и только по нашим службам.
- Профиль хранит ссылку подписки с правами `600` и не попадает в метрики.

## Чего не делаем

Веб-панели с авторизацией, графиков в реальном времени, учёта трафика по
клиентам, хранения посещённых доменов, полной выгрузки журнала на сервер.

## Риски

- **VPS нездоров по вводу-выводу.** Следящая машина сама подтормаживает.
  Смягчение: нагрузка от роутеров ничтожна; вопрос предъявить хостеру.
- **Обновление по кнопке ломает роутер на расстоянии.** Смягчение: проверка
  здоровья после запуска и откат, подтверждение в чате.
- **Профиль хранит секрет.** Смягчение: права `600`, отдельно от метрик.
- **Роутеры друзей появятся только в октябре.** До тех пор всё проверяется на
  флинте, схема с самого начала рассчитана на несколько роутеров.
