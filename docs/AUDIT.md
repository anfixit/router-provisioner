# Router Provisioner: инженерный аудит

Дата: 2026-07-22

Область проверки:

- `router-provisioner.sh` версии 1.2.0;
- README и фактический сценарий запуска;
- NetShift 0.9.6 и sing-box 1.13.14 extended;
- OpenWrt 25.12.5 с пакетным менеджером `apk`;
- холодный старт на Cudy WBR3000UAX v1;
- тесты и GitHub Actions.

## Итог

Версия 1.2.0 содержала много защитных проверок, но архитектурно оставалась хрупким монолитом. Главная эксплуатационная проблема заключалась не в синтаксисе конфигурации, а в недетерминированном порядке запуска NetShift, WAN и удалённого ruleset `russia_outside.srs`.

После ручного восстановления и полного reboot роутер успешно поднялся. Это подтверждает, что конфигурация совместима, но не опровергает гонку готовности при первом запуске. Поэтому исправление выполнено на уровне lifecycle, а не ручной правкой сгенерированного `/etc/sing-box/config.json`.

## Критические и высокие риски

### 1. Ранний запуск NetShift до готовности WAN

Симптом:

```text
initialize rule-set: russia_outside.srs: io: read/write on closed pipe
```

Последствия:

- sing-box входит в crash loop;
- nftables продолжает направлять трафик в неработающий TProxy;
- DNS может быть переключён на неслушающий `127.0.0.42`;
- пользователь воспринимает это как полную потерю интернета.

Исправление v2:

- штатный автозапуск NetShift отключён;
- добавлен guard-сервис с `START=99`;
- проверяются `network.interface.wan`, default route и загрузка ruleset;
- запуск ограничен двумя попытками;
- после повторного провала NetShift останавливается.

### 2. Монолит и патчинг внутренних файлов NetShift

Версия 1.2.0 превышала 2200 строк и добавляла код непосредственно в файлы `/usr/lib/netshift`.

Риски:

- обновление NetShift может заменить патч;
- изменение upstream-структуры ломает `awk`-вставки;
- повторный запуск трудно анализировать;
- тесты проверяют детали реализации вместо устойчивого контракта.

Исправление v2:

- код разделён на четыре модуля;
- жизненный цикл NetShift контролируется внешними helper и init-сервисом;
- сгенерированный JSON не редактируется вручную;
- тестируется контракт запуска и восстановления.

### 3. Интерактивный установщик и запуск через pipe

Интерактивный shell-скрипт не должен запускаться через `curl | sh`: stdin занят конвейером.

Исправление v2:

- `router-provisioner.sh` стал загрузчиком;
- runtime сначала скачивается в отдельные файлы;
- затем выполняется через `exec /bin/sh file`;
- README явно восстанавливает stdin/stdout через `/dev/tty`.

### 4. Утечки ссылок подписок

Ссылки подписок являются секретами доступа. Они попадали в диагностические сообщения, присланные пользователем вручную.

Исправление v2:

- ввод выполняется без echo;
- dry-run выводит только `[REDACTED]`;
- добавлен regression test;
- CI ищет секретоподобные значения.

## Средние риски

### 5. Неограниченные recovery-циклы

Автоматический перезапуск без верхней границы маскирует первичную ошибку и создаёт длительную деградацию.

Исправление v2: одна первичная и одна повторная попытка.

### 6. Обновление подписки без транзакционного отката

Неудачная новая подписка могла заменить рабочий кеш.

Исправление v2:

- сохраняются каталог подписок и рабочий JSON;
- проверяются sing-box и FakeIP;
- при ошибке возвращается предыдущая версия.

### 7. Нативный status NetShift не отражает реальное состояние

`/etc/init.d/netshift status` может показывать `inactive`, когда sing-box и monitor работают.

Рекомендованная проверка:

```sh
netshift global_check
pgrep -af 'netshift|sing-box'
logread -e router-provisioner-boot
```

### 8. Работа с `/tmp`

Backup и runtime-файлы в `/tmp` исчезают после reboot.

README теперь отдельно требует скопировать backup на компьютер до перезагрузки.

## Низкие риски и технический долг

- Автоматическая установка youtubeUnblock больше не является частью core lifecycle. Она должна быть отдельным опциональным модулем с собственными версиями, SHA-256 и тестовой матрицей OpenWrt 24.10/25.12.
- Необходим реальный smoke test на чистом OpenWrt после прохождения CI.
- Для production-релиза следует закрепить SHA-256 runtime-модулей в манифесте релиза.
- Следует добавить shell integration test с mock `ubus`, `uci`, `procd` и эмуляцией первого неудачного старта.

## Критерии принятия перед merge

1. GitHub Actions проходит без предупреждений.
2. `--diagnose` работает на OpenWrt 25.12.5.
3. Dry-run не выводит ссылку подписки.
4. Установка из ветки PR завершается успешно.
5. После полного reboot `netshift global_check` полностью зелёный.
6. В boot-логе нет новых `closed pipe`, `FATAL` и crash loop.
7. При искусственно недоступном GitHub guard не оставляет роутер без обычного DNS.
