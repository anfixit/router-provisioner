# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выпускаются для актуальной версии в ветке `main`.

## Как сообщить об уязвимости

Не публикуйте уязвимость в открытом issue, если она может привести к:

- удалённому выполнению команд;
- утечке ссылки подписки, паролей или ключей;
- блокировке доступа по SSH;
- повреждению файловой системы;
- форматированию неправильного устройства;
- обходу подтверждений опасных операций.

Используйте GitHub Private Vulnerability Reporting, если эта функция доступна в разделе Security репозитория.

Если приватный канал недоступен, создайте issue без технических деталей и попросите владельца проекта предоставить безопасный способ связи.

## Что указать в сообщении

- версию Router Provisioner;
- модель и аппаратную ревизию роутера;
- версию OpenWrt;
- точные шаги воспроизведения;
- фактический и ожидаемый результат;
- оценку влияния;
- минимальный безопасный пример без реальных секретов.

Не прикладывайте полные backup-архивы OpenWrt. Они могут содержать пароли, SSH host keys, Wi-Fi credentials, сертификаты и ссылки подписок.

## Обработка сообщения

После подтверждения проблемы будет подготовлено исправление, тест на регрессию и описание безопасного обновления. Срок публикации зависит от сложности и риска эксплуатации.

## Границы ответственности

Автоматическое изменение U-Boot, MTD, UBI и внутренней разметки не входит в универсальный сценарий проекта. Такие изменения требуют отдельной реализации и проверки для конкретной модели и аппаратной ревизии.
